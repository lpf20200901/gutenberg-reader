# 中文排版差异实录

这份文档记录的是**实测数据**，不是设计意图。

它存在的理由：这个项目里几乎所有 bug 都来自「假设另一个转写文件和手上这个一样」，
而每次假设错误都**不会报错**。把数据写下来，是为了让下一个人（包括三个月后的我自己）
不用重新踩一遍。

测量对象：Project Gutenberg 上九本中文书 + 一本英文对照，共约 300 万字。

---

| 警世通言 | `24141` | `indent` | 40 | 40 | — | 2,470 | 151 |
| 醒世恒言 | `24239` | `indent` | 40 | 40 | — | 3,251 | 164 |
| 初刻拍案惊奇 | `57248` | `indent` | 40 | 40 | — | 2,384 | 165 |

## 二、章标题格式：七种

全部来自真实文件。`→` 后面是解析器输出的结构。

### 2.1 卷标记与标题同行，空格分隔

出处：喻世明言 `#27582`、警世通言 `#24141`

```
第一卷　蔣興哥重會珍珠衫
→ [h1] 第一卷 / [h2] 蔣興哥重會珍珠衫
```

分隔符是**全角空格**（U+3000）。警世通言用的是 4 个半角空格。
两种都要吃。

### 2.2 卷标记与标题同行，直接连写

出处：初刻拍案惊奇 `#57248`

```
第一卷轉運漢遇巧洞庭紅　波斯胡指破鼉龍殼
→ [h1] 第一卷 / [h2] 轉運漢遇巧洞庭紅　波斯胡指破鼉龍殼
```

"卷"字后面**一个空格都没有**。如果正则要求必须有分隔符，这一本会零识别。

### 2.3 卷标记与标题分成两行

出处：醒世恒言 `#24239`、今古奇观 `#24230`

```
第一卷
兩縣令競義婚孤女
→ [h1] 第一卷 / [h2] 兩縣令競義婚孤女
```

标题靠「短行启发式」识别（见第四节）。今古奇观一共 80 卷，全部按这个格式，
连续无重复，已逐条核对。

### 2.4 没有"第"字

出处：二刻拍案惊奇 `#26729`

```
卷一 進香客莽看金剛經 出獄僧巧完法會分
→ [h1] 卷一 / [h2] 進香客莽看金剛經 出獄僧巧完法會分
```

`卷` 后面直接跟数字，没有 `第`。聊齋志異的卷标记（`卷一` 独占一行）是同一族的
退化形式。

### 2.5 篇名在数字**前**面

出处：世说新语 `#24047`

```
德行第一
→ [h1] 德行第一
```

中文序数在这里是后缀。用「第X回」那种前缀规则去匹配，**36 篇一个都认不出来**。

### 2.6 标题用 CJK 书名号

出处：聊齋志異 `#51828`

```
〈考城隍〉
→ [h2] 考城隍（书名号被剥掉）
```

用 `〈 〉`（U+3008/U+3009）。注意《金剛經》《內經》这类**正文引文**也用书名号，
全文共有 523 处书名号，但只有 496 处是篇名——剩下 27 处是引文，不该当标题。
实测最终 496 个 `<h2>` 与原文篇名交叉比对，**误判 0 个**。

### 2.7 裸条目号

出处：世说新语 `#24047`

```
1.
陳仲舉言，為士則行為世範。
→ [en] number=1, text=陳仲舉言，為士則行為世範。
```

条目号**单独占一行**，正文在下一行。全文 1,129 条。

## 三、分段约定：三种，以及为什么它是难点

### 3.1 空行分段（`blank`）

出处：聊齋志異、世說新語

```
    陽信某翁者，邑之蔡店人。……
(空行)
    東曦既上，家人畢集……
```

最直观，也是我最初**唯一**支持的约定。

### 3.2 行首缩进（`indent`）—— 真正踩坑的地方

出处：六本（三言二拍 + 今古奇观）

```
'　　這首詞名為《西匯月》，是動人安分守己…'   ← 缩进 = 新段落
'色、財、气四宇，損卻精神，虧了行止…'        ← 无缩进 = 续行
```

缩进字符有**两种**，且分布不均：

| 书 | 全角空格缩进 | 半角空格缩进 | 无缩进 |
| --- | --- | --- | --- |
| 醒世恒言 | 3,250 | 0 | 102 |
| 初刻拍案惊奇 | 0 | 2,377 | 64 |
| 警世通言 | 2,475 | 0 | 46 |
| 喻世明言 | 2,466 | 0 | 10,713（续行） |
| 今古奇观 | 7,871 | 2 | 23,220（续行） |

**关键**：在判断段落边界之前先 `str.strip()`，这个信号就没了。
我第一版正是如此，结果：

```
初刻拍案惊奇   40 卷  →  42 段（平均每段近一万字）
```

### 3.3 硬换行（`unwrap`）

出处：二刻拍案惊奇 `#24162`（**已弃用，见第六节**）

```
嘗記《博物志》云：“漢劉褒畫《雲漢圖》，見者覺熱；又畫
(空行)
《北風圖》，見者覺寒。”竊疑畫本非真，何緣至是？然猶曰人
(空行)
之見為之也。……
```

每行约 28 字，**每一行后面都插一个空行**。全文 10,334 个空行、10,318 行正文——
按空行切分会把一个完整段落切成十几块（实测 `blocks=10,317`）。

### 3.4 模式判定规则

```
indent  ← 缩进行数 ≥ 50 且 缩进行数 > 空行数 + 50
unwrap  ← 中位行长 ≤ 45 且 无句末标点的行占比 ≥ 0.35
blank   ← 其余
```

第一个条件用 `> 空行数 + 50` 而不是比例，是因为「缩进多、空行少」才是灾难性组合；
反过来（两者都多）用哪个都对。实测：

| 书 | 缩进行 | 空行 | 判定 |
| --- | --- | --- | --- |
| 醒世恒言 | 3,250 | 118 | `indent` ✓ |
| 警世通言 | 2,475 | 1,884 | `indent` ✓ |
| 聊齋志異 | 1,781 | 2,305 | `blank` ✓ |

**统计时必须排除条目号**。`1.` 这种行永远不含句末标点，计入后会把世說新語
误判成 `unwrap`——它的中位行长很短、无标点行占比很高，正是 `unwrap` 的特征。

## 四、短行启发式与它的两道防线

`兩縣令競義婚孤女`（8 字、无标点、独占一行）显然是标题。但正文里也有短行。

### 防线一：只在真正独立时生效

判定条件：**下一物理行是空行**，或**下一行是条目号**。

在段落累积过程中**永远不启用**。否则硬换行的续行会被提升成标题。

### 防线二：黑名单

警世通言实测多出 4 个标题：

```
其一 / 其二 / 其三 / 其四
```

这些是**正文里的列举词**，恰好短、恰好无标点、恰好独占一行。加入黑名单后
h2 从 44 降到 40，正好对齐该书的 40 卷。

黑名单内容：`其X`、`又`、`亦`、`詩曰`、`詩云`、`詞曰`、`詞云`、`話說`、`卻說`、
`且說`、`看官`、`正是`、`但見`、`只見`、`未知`。

### 已知的良性误判

二刻拍案惊奇的 41 个 `<h2>` 里有 2 个是**词牌名**：

```
满江红
如梦令
```

它们确实是正文中词的独立标注行。渲染出来正好给词做了小标题，所以未做处理。
全部 40 本卷标题已逐条核对，除这 2 个外无误判。

## 五、繁体转简体：缺口实测

引擎：Windows `LCMapStringW`（`LCMAP_SIMPLIFIED_CHINESE`，locale `0x0804`）。

### 5.1 两个失败模式

**模式一：原样不动。** 在聊齋志異（487,759 字）上实测：

| 漏字 | 应为 | 出现次数 |
| --- | --- | --- |
| `爲` | 为 | **2,052** |
| `於` | 于 | **1,701** |
| `後` | 后 | 798 |
| `蹟` | 迹 | 96 |
| `衆` | 众 | 62 |
| `牀` | 床 | 33 |
| `盃` | 杯 | 4 |
| `蓆` | 席 | 4 |
| `粧` | 妆 | 2 |

合计 11 个字、4,800 处。注意 API **能**正确转换 `為 → 为`（464 处），
却完全不管异体字 `爲`。

**模式二：转成错的变体。**

| 源字 | 引擎给出 | 应为 |
| --- | --- | --- |
| `鍾` | `锺` | `钟` |
| `麼` | `麽` | `么` |

这一类的修补**不能靠映射繁体源字**——补丁运行时源字已经不存在了，
必须针对引擎的**输出**再映射一次。

这是测试抓出来的：

```
FAIL: test_every_patch_entry_converts (trad='鍾')
AssertionError: '钟' not found in 'x锺y'
```

### 5.2 故意不修的两个字

| 字 | 次数 | 原因 |
| --- | --- | --- |
| `藉` | 53 | 简体里本就是合法字（慰藉 / 狼藉），只有「藉口→借口」该转，依赖上下文 |
| `祗` | 7 | 与 `祇`/`只` 混用的细微变体，频率可忽略 |

无脑转换会**引入**错误而不是消除错误。

### 5.3 各书修补量

| 书 | 引擎转换 | 补丁修补 |
| --- | --- | --- |
| 今古奇观 | 211,469 | 4,217 |
| 醒世恒言 | 124,849 | 2,328 |
| 聊斋志异 | 98,899 | 4,811 |
| 二刻拍案惊奇 | 95,352 | 1,863 |
| 初刻拍案惊奇 | 91,729 | 1,428 |
| 警世通言 | 86,931 | 2,154 |
| 喻世明言 | 73,693 | 3 |
| 世说新语 | 16,985 | 631 |

喻世明言只补了 3 个字——**补丁量取决于文本用了哪些字**，不是固定开销。
所以换书时应该用 `audit_gaps()` 重新校准，而不是盲目相信这张表。

## 六、下载完整性：一次差点发出残书的事故

朴素下载循环：

```python
while chunk := r.read(65536):
    f.write(chunk)
```

连接中断时 `read()` 返回空 → 循环**正常结束** → 残缺文件被当成完整的发布。
没有异常，没有警告。

在 0.02 MB/s 的慢链路上实测六个文件：

| 书 | 应有字节 | 实收字节 | 结果 |
| --- | --- | --- | --- |
| 警世通言 | 1,176,833 | 1,176,833 | ok |
| 喻世明言 | 1,130,409 | 1,119,627 | 残 |
| 醒世恒言 | 1,651,633 | 1,168,587 | 残（71%） |
| 初刻拍案惊奇 | 1,213,458 | 1,091,067 | 残 |
| 二刻拍案惊奇 | 968,635 | 813,628 | 残 |
| **今古奇观** | **2,896,630** | **724,887** | **残（25%）** |

**六分之四被静默截断。** 发现方式是拿落盘大小去比 HTTP 声明的 `Content-Length`
——唯一的线索就是这两个数字不一致。

修复后加了校验 + `Range` 续传 + 重试。续传不是理论收益：

| 书 | 失败次数 | 失败位置 |
| --- | --- | --- |
| 今古奇观 | 3 | 17%、37%、99.6% |
| 醒世恒言 | 2 | 62.8%、99.0% |
| 二刻拍案惊奇（备选版） | 1 | 64.0% |
| 初刻拍案惊奇 | 1 | 99.0% |

注意有好几次是在 **99.0%、99.6%** 处断开——差最后几 KB。没有续传的话，
每一次都要从零重下。

## 七、版本陷阱：同一本书的两个转写差异巨大

Gutenberg 上二刻拍案惊奇有两个条目：

| 编号 | 卷数 | 正文字数 | 排版 |
| --- | --- | --- | --- |
| `24162` | 28 卷 | 301,252 | 每行 28 字、行行插空行 |
| `26729` | **39 卷** | 413,520 | 段首缩进，正常 |

二刻拍案惊奇的标准版是 40 卷。**`24162` 少了 11 卷**，而且排版是碎裂的。
如果不做版本对比就随便取一个，会得到一本残缺且难读的书。

同类情况：搜 `Strange Stories from a Chinese Studio` 会返回三个条目
（`43629` 合集 + `43627`/`43628` 分卷）。

**教训：同一个书名在档案库里可能对应多个质量不同的转写，要按卷数/字数/排版选。**

## 八、其它踩过的坑

### 8.1 Gutenberg 两种页面用不同的 CSS 类

| 页面 | 类名 |
| --- | --- |
| `/browse/languages/<lang>` | `<li class="pgdbetext">` |
| `/ebooks/search/?query=` | `<li class="booklink">` |

按其中一种写正则、拿去解析另一种，会返回**零结果**——不报错，就是空列表。
我第一版正是如此，中文书目抓出来是 0 条。

### 8.2 控制台会把中文压成乱码

Windows 控制台代码页不是 UTF-8 时，Python 输出的中文会变成 `����`。

这是**显示**问题，数据是好的——但足以让人把好的解析器误判成坏的。
我为此浪费了两轮排查。做法：**让脚本写 UTF-8 文件，再读文件**；
必要时给 PowerShell 设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`。

### 8.3 主题不能靠系统推断

阅读页最初跟 `prefers-color-scheme`（操作系统设置），而宿主程序有**自己的**主题设置。
在「系统浅色 + 宿主深色」的组合下，页面渲染成白色，躺在深色面板里。

如果宿主能告诉你它的主题，就**问它**，别从操作系统猜。

### 8.4 目录改名会重置阅读状态

阅读进度和字号存在 `localStorage`，键是**文件路径**。所以改目录名 = 换路径 = 状态清零。
自包含的 HTML 本身不受影响（正文内嵌），但状态会丢。

## 九、验证方法

重构（把脚本拆成库）最大的风险是**默默改坏行为**。所以每一步都拿真实语料回归：

1. **单元测试**：40 个，每个对应一本真实书里的一个坑，`python run_tests.py` 零依赖运行
2. **语料回归**：九本书逐项对比重构前后的标题数、条目数、段落密度（`mismatches: 0`）
3. **交叉核对**：聊齋志異的 496 个标题与原文 523 处书名号交叉比对，确认无误判
4. **连续性核对**：今古奇观的 80 卷、二刻拍案惊奇的 39 卷，逐条确认编号连续无重复
5. **覆盖度审计**：用 480 对繁简参照表探测引擎，统计缺口并排序

第 2 项是最有价值的一步——单元测试只能证明"我测的这几条对"，
语料回归才能证明"我没有把原来对的东西改坏"。
